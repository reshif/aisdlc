# Runbook: the first live exit (M8.5), Census of reshif/asf-factory-testbed

What this does: you run the whole factory on your own machine, point it at one real GitHub
repository with a read-only GitHub App, and onboard that repository at the **Census** level in your
browser. At the end the factory shows you what it sent to GitHub (reads only), what the App is
allowed to do, and that its ledger checks out. Nothing is written to GitHub. The factory never
merges anything.

Time: about 20 minutes of clicking, plus the first image build (a few minutes).

## 0. What you need

- Docker with Compose v2 (`docker compose version` works), `openssl`, `curl`.
- The GitHub App you created for this, with **read-only** permissions (Contents and Metadata only).
  The `Commit statuses` permission is **not** granted (decision DEC-7).
- The App installed on **only** `reshif/asf-factory-testbed` (a "selected repositories" install).
- Ports 8340 and 8390 free on your machine.

## 1. Get the checkout ready

```
cd aisdlc/platform/compose
```

Everything below is run from this folder (`platform/compose`).

## 2. Put the App's private key in place (and why it stays there)

1. Open the App's settings on GitHub: your profile picture, Settings, Developer settings, GitHub
   Apps, your App, "Edit". Scroll to **Private keys** and press **Generate a private key**. GitHub
   downloads a `.pem` file.
2. Move that file to exactly this path and lock it down:

   ```
   mv ~/Downloads/<the-downloaded-name>.pem secrets/github-app.pem
   chmod 600 secrets/github-app.pem
   ```

**The key never leaves this folder.** It is the one secret that lets anyone act as your App. The
stack mounts it into a single container (the codehost), which signs short-lived tokens with it and
asks GitHub for read-only ones. No other container can see it, the browser never gets it, and
`secrets/` is git-ignored. Do not paste it into a chat, an issue, an email or this repository, and
do not let anyone (including an assistant) ask you to. If you think it leaked, delete the key on the
App's settings page and generate a new one.

## 3. Find the two numbers

- **GITHUB_APP_ID**: on the App's settings page ("About" at the top), the line **App ID**. A number
  such as `1234567`. (Not the Client ID, which has letters.)
- **GITHUB_INSTALLATION_ID**: GitHub, Settings, Applications, **Installed GitHub Apps**, press
  **Configure** next to your App. The address ends in `/installations/<number>`. That number is the
  installation id. (If the App is installed on an organization, use the organization's settings
  instead.)

While you are on that page, check the two things the factory will also check later: under
"Repository access" only `asf-factory-testbed` is selected, and under "Permissions" you see only
Contents and Metadata, both **Read-only**, with no "Commit statuses".

## 4. Who you sign in as

The factory's sign-in page is a stand-in for the company identity provider. The person who may
onboard is **alice** ("Alice Example (factory admin)"), whose GitHub login is `reshif`. If the repo is
owned by someone else, open `config/idp-seed.json` and put the owner's GitHub login in alice's
`"logins"` before the first start.

## 5. Start it

```
export GITHUB_APP_ID=<your App ID>
export GITHUB_INSTALLATION_ID=<your installation id>
./live-census.sh
```

(The same thing from the repo root: `npm run live:census`.) It checks everything above, builds the
image, starts the stack and prints the portal address. Add `--repo owner/name` for another
repository. Add `--wait-for-prr` to have the script wait while you work in the browser and then
print the result by itself.

## 6. In the browser, card by card

Open <http://localhost:8340>: it goes straight to the sign-in page; sign in as **alice**.

1. **Onboard a repo.** Owner `reshif`, name `asf-factory-testbed`, project slug `testbed`, level
   **Census**, then "Request onboarding". The page shows progress ("0.1 waiting: App not installed"
   means the App is not on this repo, see Troubleshooting). It takes a minute or two to reach
   "waiting for card 1".
2. **Inbox, Card 1: confirm the census.**
   - Gaps: for each gap pick **Fix later** (or **Fix now** where that is the only choice: blocking
     gaps cannot be waived). You are not fixing anything in this run.
   - Tier you sign: choose **T0** if it is offered, and tick *"no prod, no real data, no
     dependants"*. That is true of the testbed and it is the positive statement the factory needs
     (DEC-4). If the factory shows a higher tier floor, keep it: you can only raise, never lower.
   - Tick the regulatory statement ("no regulatory obligation") and the criticality statement if
     they are shown.
   - Press **Approve card 1**.
3. **Card 4: settings and who can do what.**
   - The controls table should show no **Not met** row. If one is, fix it on GitHub as its text says
     and press **Re-check**.
   - Tick every statement you have actually checked on GitHub: bypass list has no factory App, App
     on selected repositories only, default `GITHUB_TOKEN` read-only, "Actions may create/approve
     PRs" off, fork-PR approval required.
   - **Which GitHub plan is the owner of this repository on?** GitHub does not tell the factory, so
     you say it: Free, Pro, Team or Enterprise. Choose what is true (your account page says). A
     private repository on Free cannot enforce rulesets, which is why the card asks. Choosing "I do
     not know" is allowed but leaves the identity gap RS-ID-4 open, and then the readiness record
     cannot be signed.
   - Secret scanning: pick "on where the plan allows" or "not available on this plan", whichever is true.
   - Who can do what: put `alice` in the **admin** slot and in the **m4** slot. Leave the rest as
     proposed. Turn the two-person rule **off** (you are one person, and T0 allows it).
   - Gating profile and kill delegations: leave as they are.
   - Press **Approve card 4**.
4. **Settings revision.** Back on the onboarding record page a link "Decide the settings revision"
   appears. Open it, read the role map, press **Approve and publish these settings**. Card 5 cannot
   open until this is published.
5. **Card 5: sign off.** Open it. It shows the level (**census**), what the record allows and the
   record hash. Tick "I have read this readiness record". Press **Confirm my identity**: you go to
   the stand-in sign-in page again (this is the step-up); pick **alice** again. You return to the
   card. Tick the box again and press **Sign off and approve M4**.
6. The readiness record page should now say **active**, level **census**.

## 7. Read the result

If you did not use `--wait-for-prr`, run:

```
./live-census.sh --report
```

It prints four blocks and ends with `live-census: PASS` or a list of problems:

1. **What the factory sent to GitHub.** Requests grouped by method and path (names in braces stand
   for the repo, branch and so on, so no values are shown). You want to see only `GET` lines. The
   token mint (`POST .../access_tokens`) is listed apart: that is the App asking for a read-only
   token, it reads nothing. `GIT_FETCH` lines are read-only downloads of the repo. The script
   asserts this.
2. **The App's permissions** as GitHub reports them. Expect `contents=read` and `metadata=read`,
   `selection=selected`, and the line "ASSERTED: 'statuses' is absent".
3. **S0 and the readiness record.** S0 `done`; the record `active`, level `census`, with its version
   and `record_hash`, and the plan you attested.
4. **verify-ledger.** The script waits for the next checkpoint (every 5 minutes), then checks the
   whole ledger offline with the Notary's and the Witness's public keys. It must say `ledger OK` and
   `checkpoints OK`.

Keep that output: it is the recorded log for the milestone. For the demo, the portal's ledger page
lists every decision you made, each linked to its ledger entry.

## 8. Tear down

```
./live-census.sh --down          # stops it, keeps the database (the ledger and the record survive)
./live-census.sh --down --purge  # also deletes the database: everything is gone
```

Your App key stays in `secrets/github-app.pem` either way. To remove it, delete the file (and the
key on GitHub if you will not use it again).

## Troubleshooting

- **"0.1 waiting: App not installed" and it never moves.** The App is not installed on this repo,
  or the installation id is wrong. Check Settings, Applications, Installed GitHub Apps, Configure:
  the repo must be listed under Repository access, and the number in the address must equal
  `GITHUB_INSTALLATION_ID`. Fix it, then `./live-census.sh --down`, set the right id, start again.
- **The report says the App still has `statuses`.** Open the App's settings, Permissions and events,
  set Commit statuses to "No access", save; then on the installation page accept the permission
  change. Run `--report` again.
- **The report says the App is installed on all repositories.** On the installation page choose
  "Only select repositories" and pick the testbed.
- **"port 8340 / 8390 is already in use".** Another program (or an earlier run) holds it. Run
  `./live-census.sh --down`; if it still complains, find the program with `lsof -i :8340` and stop it.
- **"the App key ... mode must be 600".** `chmod 600 secrets/github-app.pem`.
- **The image build fails at apt or npm.** Your network blocks it. See "Using a real GitHub App" in
  `platform/compose/README.md` for building the image yourself, then use `--skip-build`.
- **Card 5 never opens.** Something blocks the record: usually a blocking gap still open or the
  settings revision not published. The onboarding record page says which. `docker compose logs core`
  (from this folder) shows the exact refusal, for example `blocking_gap_open` or `risk_unattested`.
- **The report says "no checkpoint covers the ledger head".** The checkpointer runs every 5 minutes;
  run `--report` again in a few minutes.
- **Start over completely.** `./live-census.sh --down --purge`, then step 5 again.
